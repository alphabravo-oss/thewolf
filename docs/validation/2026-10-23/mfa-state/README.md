# D07.2 — atomic MFA state updates

2026-10-23. The production-router reproduction forces two MFA login requests to read the same recovery-code snapshot. Previously both requests succeeded, for both the same code and distinct codes. Each then overwrote the entire stored list, allowing a recovery code to authenticate twice and allowing concurrent writes to undo consumption. A separate reproduction shows that activating an already active enrollment replaced its recovery-code set.

SQLite and PostgreSQL now share one conditional SQL update. It replaces the MFA secret, enabled flag and recovery-code list only while all three still match the caller's read snapshot and the user identity matches. Every MFA writer uses it: setup, activation, disablement, recovery/TOTP login and administrator reset. A lost race returns `409 mfa_state_changed`; a storage error returns a private 500. Neither path publishes enrollment secrets, recovery codes, access/refresh credentials or cookies. Already active enrollment returns `409 mfa_already_enabled` without replacing codes. General profile updates remain separate and are not overwritten.

The comparison is of MFA state, not an added monotonic credential epoch; no schema migration is needed. Normal TOTP login also checks the verified enrollment still matches before issuing credentials, but this is not TOTP-step or challenge replay protection.

## Remaining boundaries

A caller whose different recovery code lost a race can retry that code against fresh state. A consumed code stays consumed. Changes to enrollment/reset require reading the current state again; the server does not retry an operation against a different secret automatically. Active recovery codes are never regenerated by repeating activation.

Consumption commits before session issuance. A later session-storage/network failure can therefore consume a code without delivering a session; the caller needs another unused code or the ordinary recovery path. Atomic challenge/session issuance is not qualified here. Single-use challenge identifiers, TOTP-step replay protection, enrollment/session invalidation, mandatory-policy read failures, distributed login-failure accounting and bootstrap/break-glass qualification remain D07/A03. This is a specific MFA state race repair, not acceptance of the entire authentication system. Nothing was deployed.
